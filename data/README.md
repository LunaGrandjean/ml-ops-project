# Inside data

The real data is not stored in Git. It comes from the Inside archive (`Project.zip`)
and is versioned with DVC. Do not publish the Inside data on GitHub.

| Folder | Content | Versioned with |
| --- | --- | --- |
| `data/source/` | Original Inside files: `GBG500.parquet`, `GBG500_labels.csv`, `data.txt` | DVC (`data/source.dvc`) |
| `data/raw/<CLASS>/` | 30 s window images generated by `convert.py` | DVC output of the `convert` stage |
| `data/processed/` | `manifest.json`: image list, SHA-256, split | DVC output of the `prepare` stage |

## Source data versioned with DVC

The original Inside files live in `data/source/` and are tracked by DVC
(`data/source.dvc`, ~29 MB). Git only stores the fingerprint; the files are in the DVC
remote `storage` = `s3://datasets/dvc` on MinIO (`http://localhost:9000`).
`SRV3490.parquet` is not tracked (not required by the brief).

```bash
export AWS_ACCESS_KEY_ID=<MINIO_ROOT_USER> AWS_SECRET_ACCESS_KEY=<MINIO_ROOT_PASSWORD>
uv run dvc pull                                  # download the data
uv run dvc add data/source && uv run dvc push    # after changing the data
```

MinIO runs locally, so each member first pushes the data to their own MinIO
(copy the Inside files into `data/source/`, then `uv run dvc push`).
Never use a personal path such as `C:/Users/...` as the group remote.

## From rides to images

`src/trajectory_mlops/data/convert.py` (DVC stage `convert`) turns each ride into
grayscale images saved in `data/raw/<CLASS>/<RIDE_ID>_w<NN>.png`:

- each ride is cut into 30 s windows (300 samples at 10 Hz); the incomplete tail is dropped;
- one horizontal band per signal (`ax ay az rx ry rz`), one pixel column per 0.1 s;
- light = low value, dark = high value, with the **same fixed range for every image**
  (`convert.ranges` in `params.yaml`), so a strong shake looks dark in every ride;
- missing sensor rows are filled from neighbouring values;
- label spellings from the CSV are mapped to the class names in `config.py`
  (e.g. `Safe overall` → `Safe Overall`).

Result: 4,849 images (Safe 4,021, Safe Overall 375, Bad Weather 226, Tandem 160,
Reckless 67). Regenerate them with `uv run dvc repro convert`.

Expected folder contract (exact names, spaces and capitals included):

```text
raw/
├── Safe/*.png
├── Safe Overall/*.png
├── Bad Weather/*.png
├── Tandem/*.png
└── Reckless/*.png
```

## Split by ride

`prepare.py` (DVC stage `prepare`) checks every image, refuses binary duplicates,
writes a manifest with SHA-256 fingerprints and freezes a deterministic split.
**All windows of a ride go to the same split** (70/15/15 of the rides of each class,
with at least one ride per class in validation and test). Windows of the same ride
look alike, so splitting them would leak test information into training. Each class
needs at least 3 rides. Keep the test set out of hyperparameter choices.
